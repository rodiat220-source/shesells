# SheSells 教练 UI 触发模板

> 用途：演示和验收当前前端的教练状态。
> 开发预览页：`/dev/coach-states`

---

## 1. 状态总览

| 状态 | 触发方式 | 预期 UI |
| --- | --- | --- |
| `probe` 主动追问 | 第一轮直接推荐产品，且没有提问 | 淡黄色教练提示卡片，输入框保持可用 |
| `feedback` 即时反馈 | 先共情顾客担心，再询问使用史或给安全步骤 | 蓝绿色教练反馈卡片，输入框保持可用 |
| `halt` 主动喊停 | 第二轮仍然没有回应“敏感、刺痛、安全、耐受”等顾虑 | 红色教练喊停卡片，输入区禁用并出现确认按钮 |
| `loading` 思考中 | BA 发送消息后，等待接口返回 | 对话流底部出现三点思考动画 |
| `summary` 训练总结 | 点击“结束训练” | 当前对话流内出现总结卡片，包含最终雷达图和关键时刻 |
| `champion_replay` 销冠对比 | 点击“结束训练”后紧接 summary | 当前对话流内出现“你的回复 vs 销冠回复”对比卡片 |

---

## 2. 可演示对话脚本

这条脚本的目标是：在同一个训练会话里，按顺序展示核心教练 UI。

不要依赖随便聊天自然触发所有状态。真实用户对话是开放的，但 Demo 需要可控，所以我们用固定话术稳定触发。

### 2.1 触发 probe

顾客开场：

```txt
你好，我最近看到早 C 晚 A 很火，但我皮肤有点敏感，怕用了会刺痛烂脸，你能帮我看看吗？
```

你输入：

```txt
我推荐你直接买这套早 C 晚 A，很适合你。
```

预期：

- 出现 `probe` 教练消息。
- 教练提醒你不要急着推荐，要先了解使用史和耐受情况。
- 输入框保持可用。

为什么会触发：

BA 跳过探询，直接推荐产品。前端会渲染后端返回的 `coachType: "probe"`。

---

### 2.2 触发 halt

顾客开场：

```txt
你好，我最近看到早 C 晚 A 很火，但我皮肤有点敏感，怕用了会刺痛烂脸，你能帮我看看吗？
```

第 1 轮输入：

```txt
我推荐你直接买这套早 C 晚 A，很适合你。
```

第 2 轮输入：

```txt
很多人都在用，效果也不错。
```

预期：

- 出现 `halt` 教练消息。
- 红色提示卡片强调“关键顾虑未被回应”。
- 输入区切换成暂停态。
- 底部出现“明白了，继续”按钮。

为什么会触发：

顾客已经表达“敏感、刺痛、泛红”的担心，但 BA 第 2 轮仍然只用泛泛背书回应，没有接住顾虑。前端会根据 `metadata.requiresAction: true` 进入暂停态。

---

### 2.3 触发 feedback

点击“明白了，继续”后输入：

```txt
你担心刺痛是很正常的，我们先从低浓度、低频率开始，搭配修护霜观察两周。
```

预期：

- 出现 `feedback` 教练消息。
- 教练肯定你修正了回应方式。
- 输入框保持可用。
- 左侧实时雷达图更新。

为什么会触发：

BA 先共情了“刺痛/敏感”的顾虑，并给出低频、低浓度、修护观察的安全步骤。前端会渲染后端返回的 `coachType: "feedback"`。

---

### 2.4 继续推荐阶段

继续输入：

```txt
如果你能接受，我们先选温和 VC、低浓度 A 醇和修护霜，先低频建立耐受。
```

预期：

- 顾客继续追问。
- 左侧雷达图继续更新。
- mock 顾客回复不会在 5 轮后停止。

为什么：

当前 mock 已经扩展了顾客回复，并且超过预设轮数后会循环生成后续追问，用于支撑完整 Demo。

---

### 2.5 触发 summary 和 champion_replay

任意对话进行中，点击：

```txt
结束训练
```

或者自然对话达到 12 轮。

预期：

- 不跳转独立复盘页。
- 当前对话流内先出现 `summary`。
- 紧接着出现 `champion_replay`。
- `champion_replay` 用 side-by-side 对比：左边/上边是你的回复，右边/下边是销冠回复。
- 输入区变成完成态，显示“本次训练已完成”和“再练一次”。
- 左侧实时雷达图更新到最终评分。

为什么会触发：

`/api/finish` 返回两条教练消息：`summary` 和 `champion_replay`。前端按返回顺序追加到当前消息流。

## 3. 开发预览页

打开：

```txt
/dev/coach-states
```

可以一次性看到：

- `probe`
- `feedback`
- `halt`
- `loading`
- `summary`
- `champion_replay`

这个页面使用 `src/lib/data/coachStateFixtures.ts` 的固定假数据，不依赖真实后端判断。

## 4. 前后端对齐点

真实后端接入时，需要保持以下字段：

```ts
{
  newMessages: Message[];
  updatedState?: Partial<CustomerState>;
  updatedDimensions?: Dimensions;
  sessionStatus: "active" | "halted" | "completed";
}
```

前端行为：

- `newMessages` 按原顺序追加。
- `updatedDimensions` 更新实时迷你雷达图。
- `coachType: "halt"` 且 `metadata.requiresAction === true` 时进入暂停态。
- `sessionStatus: "completed"` 时输入区进入完成态。
