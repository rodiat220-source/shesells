# SheSells —— 顾客画像标签化：产品需求文档（PRD）

> 文档日期：2026-07-16
> 用途：将「单一硬编码画像（敏感肌新手）」升级为「用户按标签自选 → LLM 生成消费者画像 → 针对该画像做销售 coach」
> 关联文档：`SheSells-AI销售教练-项目规划.md` V3.0 / `SheSells-技术详设.md` V2.0 / `prompts.ts` / `SheSells-执行规划.md`
> 决策状态：✅ 已与产品确认（见文末决策记录）

---

## 一、背景与目标

### 1.1 现状问题

当前 Demo 只内置了一种顾客画像——「敏感肌新手想试早C晚A」，且相关内容（顾客人设、销冠对比逐字稿、SKU）全部硬编码。这带来两个问题：

1. **画像单薄**：只有一种顾客，展示不出"平台适配任意客群"的能力，容易被评委认为是"单场景 Demo"。
2. **让销售自由描述客户不稳妥**：在黑客松时间限制下，若让 BA 用自然语言自由描述客户，LLM 识别容易跑偏，现场翻车风险高。

### 1.2 方案与目标

产品内置**结构化标签**，让用户勾选组合，再由 LLM 生成完整消费者画像，针对该画像做销售 coach。

- **稳妥**：标签是有限集合，组合可控，LLM 生成画像比解析自由文本稳定得多。
- **平台感**：从"一个场景"升级为"任意客群一键生成画像"，强化"不是套壳"的叙事。
- **参与感**：评委自己选标签 → 看到生成画像 → 开始练，ownership 更强。

### 1.3 核心变更一句话

> 首页从「点一个按钮直接进入敏感肌场景」改为「选标签（年龄+肤质必选，顾虑选填）→ 生成消费者画像 → 开始针对该画像的销售训练」。**不保留快速入口**，所有对话都从选标签开始。

## 二、功能需求

### 2.1 标签选择页（新增，替代原首页）

#### 2.1.1 标签维度定义

| 维度 | 选择方式 | 是否必填 | 选项 |
|------|---------|:---:|------|
| **年龄** | 单选 | ✅ 必填 | `18-25岁`、`26-35岁`、`36岁以上` |
| **肤质·油性** | 单选 | ✅ 必填 | `油皮`、`干皮`、`混合皮` |
| **肤质·敏感度** | 单选 | ✅ 必填 | `敏感肌`、`非敏感肌` |
| **主要顾虑** | 文本输入 | ⬜ 选填 | 用户自由填写一段话（如"希望淡化红血丝的高性价比产品"） |

> 说明：肤质拆成两个正交维度——「油性」（油/干/混合）和「敏感度」（敏感/非敏感）。二者组合更贴近真实肤质描述（如"敏感+干皮""非敏感+油皮"）。

#### 2.1.2 校验规则

- 年龄、肤质·油性、肤质·敏感度**各必选 1 个**，缺任一不允许生成画像（生成按钮置灰或提示）。
- 主要顾虑非必填，可留空。

### 2.2 画像预览（生成后展示）

用户点「生成消费者画像」后，展示生成结果，包含：

1. **画像描述句（纯拼接）**：按标签顺序拼接 + 用户填写的顾虑原文。
   - 示例（填了顾虑）：`18-25岁、干皮、敏感肌、希望淡化红血丝的高性价比产品`
   - 示例（未填顾虑）：`26-35岁、油皮、非敏感肌`
   - **这句话不经过 LLM，纯前端/后端字符串拼接，保证零延迟、稳定可控。**

2. **AI 生成的画像细节**（由 LLM 生成，供展示 + 喂给顾客模拟器）：
   - 一句话人设（如"28岁，油皮，想解决 T 区出油但怕闷痘的上班族"）
   - 主要顾虑 2-3 条
   - 背景故事 2-3 句
   - 顾客开场白（作为对话第一条 customer 消息）

3. **操作按钮**：
   - `开始训练` → 进入对话页
   - `重选标签` → 返回标签页**重新开始（发起新一轮，不在旧画像上微调）**

> 重要交互约定：**重选标签 = 全新一轮对话**。不做"基于已有标签增量重新生成"。用户每次重选，都相当于创建一个全新 session。

### 2.3 训练对话（复用现有能力，画像动态化）

进入对话页后，交互与现有设计完全一致（顾客模拟 + 教练主动追问/喊停 + 对话内评分 + 销冠对比），**唯一区别是顾客画像来自用户选择的标签，而非硬编码**。

- 顾客模拟器（`CustomerSimulator`）：注入动态生成的 `CustomerProfile`。
- 顾客诉求（`goal`）：由 LLM 根据"年龄 + 肤质 + 顾虑"自动生成，不再固定为"try_early_c_late_a"。
- 顾虑列表（`concerns`）：
  - 用户填了主要顾虑 → 以用户填写内容为主。
  - 用户未填 → 由 LLM 根据"年龄 + 肤质"自动推断典型顾虑（如敏感肌→怕刺痛；油皮→怕闷痘）。

### 2.4 销冠对比：改为 LLM 实时生成（关键变更）

> ⚠️ 这是相对原技术详设最大的一处变更，务必让全组知悉。

#### 2.4.1 为什么必须改

原设计中「销冠对比」用**预写死的逐字稿库**（`championReplay.ts`，全部围绕"敏感肌 A 醇"场景）。现在画像动态化（可能是油皮控油、干皮抗初老等），预设逐字稿 100% 对不上，会出现"BA 练的是油皮控油，销冠对比却在讲 A 醇"的露馅问题。

#### 2.4.2 新方案

对话结束（`/api/finish`）时，销冠对比由 LLM **根据当前画像 + BA 本轮实际犯的错**实时生成：

- 针对 BA 犯错的关键时刻（`missed_concerns` / `criticalMoments`），生成"普通 BA 说法（反例）vs 销冠说法（正例）+ 技巧标签"的对比段。
- 生成内容必须贴合当前画像的诉求与产品品类（不再固定 A 醇）。

#### 2.4.3 兜底方案（防翻车，替代原预设逐字稿的安全牌）

| 层级 | 方案 |
|------|------|
| 主方案 | LLM 实时生成销冠对比（匹配当前画像 + 失误） |
| 兜底1 | LLM 超时/失败 → 降级为「通用型」销冠话术结构模板（不绑定具体产品，只讲技巧结构：先共情 → 给具体方案 → 降低决策成本），前端仍可正常渲染对比卡片 |
| 兜底2（演示策略） | 彩排时固定几个「验证过的画像组合」，Demo 现场优先选这些组合。产品 UI 上不体现"快速入口"，但内部知道哪些组合稳。 |

> 注：`championReplay.ts` 的固定逐字稿**作废/降级**为兜底1的通用模板来源，不再作为主路径。

## 三、数据模型变更

### 3.1 `CustomerProfile` 扩展

现有类型（`types/index.ts`）中的 `CustomerProfile` 已足够通用，只需放开硬编码约束，并新增标签来源字段：

```typescript
export interface PersonaTags {
  age: '18-25' | '26-35' | '36+';
  oiliness: 'oily' | 'dry' | 'combination';   // 肤质·油性
  sensitivity: 'sensitive' | 'non_sensitive'; // 肤质·敏感度
  concernText?: string;                        // 主要顾虑（用户填写的原文，选填）
}

export interface CustomerProfile {
  persona: string;        // 不再限定为 'sensitive_skincare_newbie'，改为 LLM 生成的人设标识/描述
  skinType: string;       // 由标签组合而来，如 '敏感+干皮'
  goal: string;           // LLM 生成的顾客诉求，不再固定 'try_early_c_late_a'
  concerns: string[];     // 用户填写 或 LLM 推断
  tolerance: 'low' | 'medium' | 'high';
  background: string;     // LLM 生成
  tags?: PersonaTags;     // 新增：记录用户选择的原始标签
  displayLine?: string;   // 新增：给用户看的纯拼接画像句
}
```

### 3.2 `Session` 关联

`Session.customerProfile` 直接存放动态生成的 `CustomerProfile`（含 `tags` 和 `displayLine`）。`scenarioId` 可保留但语义弱化（可用一个通用值如 `custom_persona`，或用 tags 派生的 key）。

## 四、接口变更

### 4.1 新增：生成画像接口

```http
POST /api/persona
Content-Type: application/json

{
  "age": "18-25",
  "oiliness": "dry",
  "sensitivity": "sensitive",
  "concernText": "希望淡化红血丝的高性价比产品"   // 选填，可缺省
}
```

Response:

```json
{
  "displayLine": "18-25岁、干皮、敏感肌、希望淡化红血丝的高性价比产品",
  "customerProfile": {
    "persona": "学生党敏感干皮，预算有限想改善泛红",
    "skinType": "敏感+干皮",
    "goal": "改善脸颊红血丝，倾向高性价比、温和的产品",
    "concerns": ["怕刺激加重泛红", "预算有限怕交智商税", "不懂成分怕买错"],
    "tolerance": "low",
    "background": "22岁女生，学生党，敏感干皮，脸颊有明显红血丝……",
    "tags": { "age": "18-25", "oiliness": "dry", "sensitivity": "sensitive", "concernText": "希望淡化红血丝的高性价比产品" },
    "displayLine": "18-25岁、干皮、敏感肌、希望淡化红血丝的高性价比产品"
  },
  "initialMessage": "你好，我脸颊老是红红的，想改善一下，但我皮肤比较敏感又是学生，预算有限，怕买贵了还没用……你能帮我看看吗？"
}
```

职责划分：
- `displayLine`：**后端纯拼接**（标签中文文案按序 + 顾虑原文），不经过 LLM。
- `customerProfile`（goal/background/concerns/persona）+ `initialMessage`：**LLM 生成**。

### 4.2 修改：创建会话接口

`POST /api/session` 接受生成好的画像（前端把 `/api/persona` 的结果传入），或接受 tags 由后端内部先生成画像再建 session。推荐前者，减少一次往返：

```http
POST /api/session
Content-Type: application/json

{
  "customerProfile": { ...上面 /api/persona 返回的 customerProfile },
  "initialMessage": "你好，我脸颊老是红红的……"
}
```

Response 结构保持不变（返回 `sessionId` + `scenario`/画像 + 首条 customer 消息）。

> 兼容做法：也可让 `/api/session` 直接接收 tags，在服务端调用画像生成逻辑，返回 sessionId。二选一，团队定，但**画像预览页需要先看到画像**，因此推荐先 `/api/persona` 再 `/api/session`。

### 4.3 不变：`/api/chat`

结构完全不变。顾客模拟器/评估教练读取的是 `session.customerProfile`，天然支持动态画像。

### 4.4 修改：`/api/finish`（销冠对比 LLM 化）

- 输出结构不变（仍返回 `summary` + `champion_replay` 两条 coach 消息）。
- **`champion_replay` 的 `replayTurns` 内容由 LLM 实时生成**（基于 `session.customerProfile` + 对话中的 `missedConcerns`/`criticalMoments`），失败时走兜底通用模板。

## 五、Prompt 变更

### 5.1 新增：画像生成 Prompt（`buildPersonaGeneratorPrompt`）

职责：根据标签 + 选填顾虑，生成 `customerProfile`（goal/concerns/background/persona）+ 开场白。要点：

- few-shot 覆盖至少 3 种不同标签组合（敏感干皮 / 非敏感油皮 / 敏感混合皮等），保证不同画像差异明显。
- 顾虑处理：填了→以用户原文为主并展开；没填→按"年龄+肤质"推断典型顾虑。
- `tolerance` 与敏感度挂钩：敏感肌→low；非敏感→medium/high。
- 严格 JSON 输出，snake_case，后端做 key-mapping。

输出 schema（示意）：

```json
{
  "persona": "学生党敏感干皮，预算有限想改善泛红",
  "skin_type": "敏感+干皮",
  "goal": "改善脸颊红血丝，倾向高性价比、温和的产品",
  "concerns": ["怕刺激加重泛红", "预算有限怕交智商税", "不懂成分怕买错"],
  "tolerance": "low",
  "background": "22岁女生，学生党……",
  "initial_message": "你好，我脸颊老是红红的……"
}
```

### 5.2 修改：`buildCustomerSimulatorPrompt`

- `customerProfile` 参数由动态画像注入（已支持，无需改结构）。
- 移除对"早C晚A/A醇"的隐性假设，改为围绕 `goal` 和 `concerns` 展开。
- few-shot 示例保留通用结构，但注释说明"顾客诉求随画像变化"。

### 5.3 修改：`buildEvaluatorCoachPrompt`

- `customerProfile` 注入动态画像。
- 评分与教练逻辑通用，无需大改；确保 prompt 中不写死"A醇/刺痛"，改为引用"顾客的顾虑（concerns）"。

### 5.4 新增：`buildChampionReplayPrompt`（销冠对比实时生成）

职责：根据画像 + BA 犯错时刻，生成销冠对比段。要点：

- 输入：`customerProfile`、关键失误列表（missed_concerns/criticalMoments）、对应轮次的 BA 原话。
- 输出：每个失误一段 `{ turn, baMessage(反例), championMessage(正例), skillTags, gap }`。
- 约束：销冠话术必须贴合当前画像品类（油皮别推 A 醇修护套餐、干皮别推控油），技巧标签沿用（先共情/给具体方案/降低决策成本/讲人话）。
- 兜底：LLM 失败 → 返回通用结构模板。

## 八、风险与兜底

| 风险 | 对策 |
|------|------|
| LLM 生成画像质量参差 | 画像生成 prompt 用 few-shot + 固定 JSON 结构；预览页提供"重选标签"（≈重来） |
| 不同画像下顾客模拟差异不够（都像同一个人） | prompt 强制注入 `concerns` 和语气特征，约束差异化；tolerance 随敏感度变化 |
| 销冠对比 LLM 化后翻车（跑题/超时/对不上画像） | 兜底1 通用结构模板；兜底2 Demo 优先选验证过的画像组合 |
| 去掉快速入口 = 去掉稳定路径 | 演示策略：UI 上"随便选"，现场实际选彩排过 N 遍的组合 |
| 画像句拼接与 LLM 画像不一致（如顾虑对不上） | displayLine 只拼接标签+顾虑原文；LLM 画像另存，二者展示分区，不强求逐字一致 |
| 组合爆炸导致 prompt 不稳 | 维度受控：年龄3 × 油性3 × 敏感度2 = 18 种基础组合，可覆盖测试 |

## 九、验收标准（在原 Demo 清单基础上新增）

- [ ] 标签页：年龄/油性/敏感度各必选，缺项无法生成（按钮置灰或提示）。
- [ ] 顾虑框选填，留空可正常生成画像。
- [ ] 点击生成后：展示纯拼接的 `displayLine` + LLM 生成的画像细节 + 开场白。
