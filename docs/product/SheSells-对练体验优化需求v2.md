## 新增问题一（P0）：打断门槛太低——大部分消息都被拦截，对话推不动

### 现象

回放对话里，BA 的 10 条回复中有 4 条触发了教练拦截（即时反馈 / 教练提示），对话几乎走一步停一步，体感上"一直被纠偏、聊不到头"。

### 当前状态说明

系统现有两种拦截状态，**均会阻断对话、要求 BA 改完重发**：

| 状态名 | 触发场景（推测） | 当前行为 |
|--------|--------------|---------|
| **即时反馈** | BA 消息有明显改进空间 | 拦截 + 给修改建议 |
| **教练提示** | BA 消息可以更进一步 | 拦截 + 给进阶建议 |

两者本质一样——都是强制拦截，只是措辞风格不同（一个偏纠错，一个偏进阶）。

### 问题所在

"有改进空间"不等于"必须改了才能继续"。当前设计把**建议类**和**纠错类**都做成了强制拦截，导致：
- BA 几乎每说一句都被拦，挫败感强
- 对话节奏被反复打断，顾客模拟失真
- 用户不清楚"说到什么程度才算过关"

### 改进方向

**按严重程度拆分两条路径：**

```
BA 发出消息
      │
      ▼
EvaluatorCoach 评估
      │
  ┌───┴───┐
  │       │
严重错误  建议/优化类
（如：        │
 完全没共情    ▼
 错误引导  放行 → 生成顾客回复
 虚假承诺）    + 在旁边显示一条轻量提示（不强制改）
  │
  ▼
拦截 → 给修改建议 → BA 必须改了重发
```

- **强制拦截（Halt）**：BA 的话有明显错误或误导，必须纠正后才能继续。
- **旁路提示（Soft Hint）**：BA 的话勉强可以，但有更好的说法，顾客正常回复，提示显示在旁边供参考，BA 不需要修改也能继续。

### 落点
- `EvaluatorCoach` 评估结果新增 `severity` 字段：`block`（拦截）/ `hint`（旁路）。
- `block` 走现有 halt 流程；`hint` 直接生成顾客回复，提示信息在 UI 旁路展示。
- prompt 中明确两者触发条件边界，避免 LLM 把建议类也判成 block。

## 新增问题二（P0）：教练反馈引入了顾客未提及的需求

### 现象

截图中顾客原话：
> "皮肤比较干但不太敏感，最近觉得法令纹和眼角的细纹变深了，想看看有没有抗老效果好一点的精华或者面霜推荐。"

顾客**只提了**：法令纹、眼角细纹、抗老。

但教练的"即时反馈"中出现：
> "补充回应**下颌线松弛**和**卡粉**两个顾虑，让顾客感到所有痛点都被看见"

**下颌线松弛和卡粉是顾客从未提及的**，教练凭空引入，导致：
- BA 按建议去说，顾客实际上没说过这些，对话出现信息断层
- 教练建议失去可信度

### 根因

`EvaluatorCoach` 在生成建议时，可能从"36岁以上干皮抗老"的**画像标签**推断出了常见顾虑（下颌线松弛、卡粉），而不是严格基于**本次对话中顾客的实际表述**。

### 改进方向

教练反馈必须**锚定对话实际内容**，不得基于画像标签做推断引入顾客未说过的需求。

```
EvaluatorCoach prompt 明确约束：
  ✅ 建议只能基于顾客在本次对话中已明确表述的顾虑/需求
  ❌ 不得引用画像标签中的常见顾虑作为建议依据
  ❌ 不得出现顾客未提及的具体症状或场景
```

### 落点
- `EvaluatorCoach` prompt 新增硬约束：**所有建议中引用的顾客顾虑，必须可以在对话历史中找到原文依据**。
- 可在 prompt 中附加 `顾客已明确表述的顾虑列表：{mentionedConcerns}`，由 `CustomerSimulator` 或对话解析模块维护，避免教练"脑补"需求。
