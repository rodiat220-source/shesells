# SheSells —— 对练体验优化需求（发研发版）

> 文档日期：2026-07-16
> 来源：真实试用后的体验反馈复盘
> 关联：`SheSells-技术详设.md` V2.0 / `prompts.ts` / `SheSells-执行规划.md` / `SheSells-AI创新设计.md`

---

## 核心理念（先对齐）

把这次模拟对练理解成一个 **有好坏结果导向的游戏剧本**：

- **保留现在的打断设计**：BA 的话只要不完美，就打断并给出修改建议。
- 但打断后要**给出前后一致、可执行的建议**，BA 照做之后，教练不能再反过来批评他执行了这条建议。
- 对话到达固定轮数后，**BA 发出最后一条消息直接触发结局**，不在顾客发言中间截断。

> 本次**不调整打断触发频率**，"不完美即打断"的设计保留。

## 问题一（P0）：教练建议前后矛盾——照着上次建议做了，被下次打断批评

### 现象（真实案例）

```
顾客：详细描述了护肤步骤和痛点（法令纹、松弛、菁纯面霜等）

BA：直接推荐产品

教练第一次打断：
  "认可你捕捉了滋润与抗老兼顾的需求。但推荐前建议先深挖痛点：
  '您松弛和细纹哪个最困扰？平时护肤习惯怎样？'
  先聚焦核心问题再推荐，转化更高效。"

BA 照做，原话问：
  "您松弛和细纹哪个最困扰？平时护肤习惯怎样？"

教练第二次打断：
  "护肤习惯顾客刚已详细回答，重复提问会显不专业。
  建议改为：'菁纯面霜用量多少？卡粉在哪个季节更明显？'"
```

教练自己叫问的，问了又说不该问。**直接让用户失去对教练的信任。**

### 根因

`EvaluatorCoach` 每轮是独立的 LLM 调用，不知道"上一轮自己说了什么建议"。第二轮只看到"BA 在问一个顾客刚说过的问题"，判断为重复提问，完全没意识到这是自己上一轮要求 BA 问的。

### 改进方向

```
第 N 轮：教练打断，给出建议 X
         → 建议 X 写入 Session.lastCoachAdvice

第 N+1 轮：EvaluatorCoach 评估前，先读取 lastCoachAdvice
  ├── BA 执行了建议 X？
  │     是 → 正向反馈，此条建议本轮不得作为打断/扣分依据
  │     否 → 继续提示同一问题
  └── 执行确认后，再评估其他维度
```

### 落点
- `Session` 新增字段 `lastCoachAdvice`，记录上轮教练建议的核心指令。
- `EvaluatorCoach` prompt 增加输入：`上一轮教练建议：{lastCoachAdvice}`，系统指令明确：**BA 本轮已执行上轮建议，该建议不得作为批评依据**。
- 可与**创新二 ErrorPatternTracker** 合并，从"追踪错误"扩展为"追踪建议是否被执行"。

## 问题二（P0）：打断后校验标准不稳——改了还是可能被驳回

### 现象
BA 按建议修改重发后，仍然被打断，且理由每次不同，不知道怎么说才算"过关"。

### 根因
重发消息走的是正常的全量 `EvaluatorCoach` 评估，LLM 每次可能换一个视角找新问题，导致"改了还是被批"。

### 改进方向

打断时**锁定本次问题**，重发只校验这一个问题，不做全量评估。

```
教练打断 → 明确记录本次问题类型（haltIssue）

BA 修改重发
        │
        ▼
专项校验：haltIssue 是否解决？
        │
   ┌────┴────┐
   │         │
 解决了      未解决
   │         │
   │    只针对 haltIssue 再次提示，不引入其他问题
   │
   ▼
解除打断 → 生成顾客回复 → 对话继续
```

### 落点
- `Session` 在 halt 状态下记录 `haltIssue`（当前待解决的具体问题）。
- 重发时走专项校验，只判断 `haltIssue` 是否解决，通过才生成顾客回复并解除 halt。
- 未通过时只针对同一问题提示，不引入新评估维度。
- 兜底：同一问题连续 3 次未通过，自动放行并在结局复盘中标记。

## 问题三（P0）：对话结束时机不对——顾客话没说完就被截断

### 现象
顾客最后一句还在问话，对话就自动触发结算了。

### 根因
现有逻辑是到达最大轮数直接截断，不管当时对话是否在顾客发言中间。

### 改进方向

**硬性轮数截断保留**，触发时机调整为：

> **到达轮数上限时，等 BA 发出本轮消息后直接触发结局**，不再生成顾客回复。

保证结局发生在一个自然的 BA 收尾节点，而不是顾客话说到一半被切断。

### 落点
- 轮数判断逻辑从"顾客发言前"移到"BA 发言后"触发结局。
- 改动量小，只需调整触发时机判断点。

## 问题四（P1）：结局缺少等级感和视觉化——有了更好的体验优化

### 现象
现在对话结束会给一个打分，但打分没有等级划分（如及格/良好/优秀），也没有对应"这局赢了还是输了"的视觉呈现，结局感不强。

### 改进方向 A：结局等级 + 三种结果分支

在现有打分基础上，用**顾客隐状态终值**（`trust` / `purchaseIntent`，字段已有，无需新建）叠加判定三种结局：

| 结局 | 触发条件（阈值可调） | 顾客收尾表现 | 结算基调 |
|------|------------------|------------|---------|
| **✅ 成交** | `purchaseIntent` 高 + `trust` 达标 | "好，那我就买这个了" | 庆祝，突出做对的关键步骤 |
| **❌ 流失离店** | `trust` 崩 / `irritationFear` 持续高 | "我再看看别家吧" | 复盘，指出关键崩盘点 |
| **⏳ 待跟进** | 中间态，有意愿未拍板 | "我回去研究一下再决定" | 指出"临门一脚"差在哪 |

### 改进方向 B：结局卡视觉化

在现有打分报告的基础上，**用一张结局卡替代或置顶**，突出"这局的最终结果"。结局卡内容简洁，三种结局共用同一套样式，只改标题文案和一个状态标签（✅ 成交 / ❌ 流失 / ⏳ 待跟进）：

```
┌────────────────────────────────────┐
│  ✅ 成交                             │   ← 状态标签（三选一，换色换文案）
│  她把心交给了你                       │
│                                    │
│  购买意愿 85 · 信任 78               │   ← 隐状态终值（复用现有字段）
│                                    │
│  ⭐ 做对的关键 2 步                   │
│  · 第3轮先共情了松弛顾虑              │
│  · 第6轮给出了匹配的替换方案          │
│                                    │
│  💡 下次可以更好                      │
│  · 促单时可以再给一点紧迫感            │
│                                    │
│  [ 查看完整复盘 ]  [ 再来一局 ]       │
└────────────────────────────────────┘
```

无需多套视觉皮肤，**只用状态标签的颜色区分三种结局**（如绿/红/橙），其余布局、字体、结构完全一致，开发成本极低。

### 落点
- `/api/finish` 新增 `outcome: 'deal' | 'churn' | 'follow_up'` + 隐状态终值 + 高光时刻 + 1 条核心建议。
- 前端结算页根据 `outcome` 渲染对应结局卡（成交=庆祝/流失=复盘/待跟进=临门一脚）。

## 汇总

| # | 问题 | 优先级 | 改动量 |
|---|------|:---:|:---:|
| 1 | 教练建议前后矛盾 | **P0** | 中 |
| 2 | 打断后校验标准不稳 | **P0** | 中 |
| 3 | 对话结束时机不对（顾客话没说完被截断） | **P0** | 小 |
| 4 | 结局缺等级感和视觉化（现有打分基础上优化） | P1 | 中 |

> 问题 1+2 本质同类（教练缺跨轮记忆），建议一起实现。问题 3 改动小，顺手做。问题 4 有了更好，不阻塞 P0。

---

## 一句话总目标

> 保留"不完美即打断"，但要做到：**教练说让你怎么改，你改了就不能再被批**；改对了标准一致、顾客自然接话；对话到点后 BA 发完最后一条消息直接触发结局——而不是"照教练说的做了反被批、不知道怎么说才对、顾客话没说完就结束了"。
